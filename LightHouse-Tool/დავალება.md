# დავალება: TravelGeorgia — Performance დიაგნოსტიკა

**ლექცია:** 1 — Performance და Core Web Vitals  
**დრო:** 2-3 საათი  
**ტიპი:** დამოუკიდებელი პრაქტიკული სამუშაო

---

## კონტექსტი

მოცემული გაქვთ `დავალების-პროექტი/` ფოლდერში არსებული ვებგვერდი — **TravelGeorgia**, ტურისტული საიტი საქართველოს შესახებ.

ვებგვერდი ვიზუალურად მუშაობს, მაგრამ **შეგნებულად შეიცავს Performance პრობლემებს**, რომლებიც ხილული იქნება DevTools-ის **Performance** ტაბში.

თქვენი ამოცანაა:
1. გაუშვათ Performance ჩაწერა (recording)
2. იპოვოთ პრობლემები
3. გამოასწოროთ

## ნაბიჯი 2: პრობლემების აღმოჩენა (40 წუთი)

Performance ჩაწერის ანალიზით იპოვეთ **მინიმუმ 10 პრობლემა**.

თითოეულისთვის ჩაწერეთ:

| # | პრობლემა | სად ნახეთ Performance tab-ში | რომელ მეტრიკას აუარესებს |
|---|---------|------------------------------|------------------------|
| 1 |გადატვირთულია გრძელი ამოცანებით (>50 მლწ) | Main thread / Flame chart (წითელი ბლოკები) | TBT (Total Blocking Time) |
| 2 | გვერდის ყველაზე დიდი ელემენტი გვიან იტვირთება | Timings ზოლი (LCP მარკერი) | LCP (Largest Contentful Paint) |
| 3 | პირველი კონტენტის გამოჩენა ეკრანზე ჭიანურდება | Timings ზოლი (FCP მარკერი) | FCP (First Contentful Paint) |
| 4 | ჩატვირთვისას ელემენტები მოულოდნელად ინაცვლებს/ხტება | Experience ზოლი (Layout shifts) | CLS (Cumulative Layout Shift) |
| 5 | სკრიპტების შესრულება ძალიან დიდ დროს მოითხოვს | Summary ტაბი (ქვემოთ) | TBT |
| 6 | რენდერინგისა და სტილების დამუშავების დიდი ხანგრძლივობა | Summary ტაბი (ქვემოთ) | FCP / Rendering |
| 7 | კოდში არსებული მძიმე ფუნქცია ზედმეტ რესურსებს ხარჯავს | Bottom-Up ტაბი | TBT |
| 8 | მძიმე რესურსების (სურათების/ფონტების) ნელი ჩატვირთვა ქსელიდან | Network ზოლი (ზემოთ) | LCP / FCP |
| 9 | სქროლვისას კადრების ჩამოვარდნა (FPS-ის დაცემა) | Frames ზოლი / სქროლ-ინტერაქცია | ანიმაციის სიმლასკე (Smoothness) |
| 10 | რენდერ-დამაბლოკებელი სტილების (CSS) ფაილი | Network ან Main thread | FCP / LCP |

### მინიშნება — სად ეძებოთ:
- **Main** thread-ის flame chart — ყურადღება მიაქციეთ გრძელ (წითელ) ბლოკებს
- **Timings** ზოლი — LCP, FCP, DCL მარკერები
- **Layout Shifts** — ნარინჯისფერი მარკერები Experience ზოლში
- **Summary** ტაბი — Scripting vs Rendering vs Painting
- **Bottom-Up** ტაბი — რომელი ფუნქციები ხარჯავენ ყველაზე მეტ დროს
- **Network** ზოლი — რომელი რესურსები იტვირთება და როდის
- **Scroll** ინტერაქცია — დასქროლეთ გვერდი recording-ის დროს

## მოსალოდნელი შედეგები

ოპტიმიზაციის შემდეგ:
- Long Tasks: 8-10 → 0-1
- TBT: 2000ms+ → <200ms
- CLS: 0.2+ → <0.05
- LCP: 4s+ → <2s
- სქროლი: janky → smooth (60fps)
- ძებნა: 200ms+ delay → instant
